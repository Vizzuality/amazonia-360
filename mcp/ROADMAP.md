# MCP roadmap

Status on 30 September 2026. The service runs in staging only. Designs are in
`docs/superpowers/specs/`, and trial reports in `docs/superpowers/evaluations/`.

## Done

- **Phase 1:**
  - catalogue in the shape of the CMS contract;
  - five area tools over stdio;
  - per-call measurement;
  - three Desktop trial rounds and a 24-hour timing run.
- **Maps:**
  - `map_area_by_category` and `map_class_shares_in_area` with MapLibre, as MCP Apps;
  - five classed rasters of the regional platform.
- **Phase 2:**
  - Streamable HTTP behind OAuth, with Google sign-in and an email allowlist in the `mcp` schema,
    managed with `amazonia360-mcp-db allow` and `revoke`;
  - state in the `mcp` schema;
  - tested end to end from Claude Code.

## Now

1. **Staging deployment.** A fourth container in the Beanstalk environment. The migration runs
   before the server, as the `mcp` role; after the first one, `amazonia360-mcp-db allow` adds
   the first emails. One instance and one worker. nginx needs:
   - `proxy_buffering off` and a read timeout above 65 s;
   - the Host header forwarded;
   - the root `.well-known` routes;
   - `limit_req` on the OAuth routes.

   Secrets follow the app's path (Terraform, then GitHub secrets). Decide how long the call log
   keeps emails.
2. **Phase 3, places and skill**
   ([spec](../docs/superpowers/specs/2026-09-30-mcp-places-and-methodology-design.md)):
   - `find_places` and `place_id` on every area tool;
   - the `amazonia360` skill, installed by hand, with the guidance on ambiguous terms.

   Local work, independent of the deployment.

   Implemented. Left: the Desktop check of the maps by place name, and the with/without skill
   round from the spec's Testing section.

## Next

3. **Quantity rasters** (AM-732). The 22 image services that call for a sum or a mean over the
   area: population, crop production, GDP.
4. **Gatekeeper evaluation.** The question classifier for the front end, Jev first and Laya
   after, with its own evaluation set. Needs the IDB's view on sending user questions to Jev.

## To decide

- **Steering the model's wording.** Recommended, not decided: figures drawn by the front end
  from the result, and rules in its system prompt (module spec, "Steering the model's wording").
- **Overlap tool.** Questions such as "deforestation inside protected areas", answered by the
  server so the model does not combine two results. It is the first candidate if the question
  recurs in the gatekeeper set. It needs a server-side clip and a class filter per layer.

## When needed

- **Sensitive layers.** Before the intangible zones (220) or any indigenous layer become
  answerable:
  - a curated `sensitive` field in the CMS contract, sent as a proposal;
  - the server returns only coarse aggregates for such layers;
  - no argument lets the model skip that rule.

## Hardening

Found in the 28 September review:
- SRI and a narrower jsDelivr entry in the map pages' CSP, tested in Desktop first;
- a host allowlist for URLs that come from the CMS;
- a ceiling on the whole call;
- tests for the pages' JavaScript;
- request size and concurrency limits over HTTP, and cancelling the clip when the client leaves.

## Data

Open with the data owners:
- provenance curation in the CMS (AM-728);
- layer 210 drawn almost transparent (AM-729);
- layer 211's class field against its renderer (AM-730);
- raster resolution stated as 250 m while the data is about 1 km (AM-731);
- no description for Carbon (206);
- name defects in the administrative boundaries (see the phase 3 spec).

## Considered, not planned

- **A plugin that bundles the skill and the server.** Not for a proof of concept; the skill is
  installed by hand.
- **Reports generated by the server from figures the model supplies.** The figures would look
  checked when they are not.
- **Freshness from `lastEditDate`.** That is the date the service was edited, not the date of the
  data.
- **A shared access token.** OAuth with per-user identity is already in place.
- **A scope rule enforced only through instructions.** It had no visible effect in the trials.
